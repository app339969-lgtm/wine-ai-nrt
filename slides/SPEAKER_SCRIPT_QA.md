## 2. คลังคำตอบ Q&A สำหรับกรรมการ (Top 8 Questions)

1. **Q: ทำไมถึงตัด Missing 750 แถวทิ้งแทนการเติมค่าเฉลี่ย/มัธยฐาน (Impute)?**
   - **A**: เพราะทั้ง 750 แถว (`1.50%`) ขาดข้อมูล **ทั้ง `Units_Sold` และ `Total_Amount` พร้อมกัน** จึงไม่มีข้อมูลปริมาณให้คำนวณย้อนกลับได้แม่นยำ การ Drop 1.50% จึงรักษาความถูกต้องเชิงตัวเลข 100% โดยไม่สร้างความคลาดเคลื่อนเทียมครับ
2. **Q: ทำไมถึงแยก Outliers 50 แถวออก ไม่ลบทิ้งถาวร และทำไมตรวจบน `Units_Sold` แทน `Total_Amount`?**
   - **A**: เพราะถ้าใช้ IQR บน `Total_Amount` โดยตรง (`Upper Fence = 6,450 บาท`) จะไปตัดบิลปกติของหมวด Household (`890 × 8–24 ชิ้น = 7,120–21,360 บาท`) ออกผิดพลาดถึง `5,250` แถว แต่เมื่อตรวจบน `Units_Sold` ทั้ง **IQR (`> 38.5`) และ Z-Score (`|Z| > 3`) จับได้ตรงกันที่ 50 แถว (`999 / 1,200 / 1,500` ชิ้น)** เราจึงแยกไว้ใน `outliers_audit.csv` ให้ฝ่ายปฏิบัติการตรวจสอบว่าเป็น Key-in Error หรือคำสั่งซื้อ B2B เหมาล็อตครับ
3. **Q: ความสอดคล้องของ FK Match Rate ได้เท่าไร?**
   - **A**: `50,000 / 50,000` แถว หรือ **`100.0%`** ผ่านเกณฑ์ `>= 99%` และ `Transaction_Date >= Signup_Date` ทุกแถวครับ
4. **Q: ทำไมระบบเว็บถึงเลือก Next.js + Pre-aggregated/Compact JSON แทนที่จะ Query CSV สดทุกครั้ง?**
   - **A**: เพื่อ Performance ครับ หน้าแรกโหลดจาก `summary.json` (38.7 KB) และกรอง 49,200 แถวจาก `transactions_compact.json` แบบ Dictionary-Encoded ในหน่วยความจำ จึงโต้ตอบ Filter/Drill-down ได้ในระดับมิลลิวินาที และรันได้เหมือนกันทั้งบน Vercel Cloud และสคริปต์ออฟไลน์ครับ
5. **Q: ถ้าอินเทอร์เน็ตในห้องแข่งขันล่ม ระบบสำรองทำงานอย่างไร?**
   - **A**: เรามี `run_dashboard.bat` / `run_dashboard.ps1` ที่รัน Production Next.js Server บน `http://localhost:3000` ได้ทันทีโดยไม่ต้องต่อเน็ต และมีสคริปต์ `clean_data.py` + `test_clean_data.py` ที่รันซ้ำได้ครบ 100% ครับ
6. **Q: ทำไมข้อมูลจริงมี 50,000 แถวและ `TXN-10001` ไม่ตรงกับตัวอย่าง 15 แถวในโจทย์?**
   - **A**: ตารางในเอกสารเป็นตัวอย่างจำลองโครงสร้าง 15 แถว ส่วนข้อมูลจริงที่ให้มาในไฟล์ CSV มีลูกค้า 1,000 ราย (`CUST-001`–`CUST-1000`) และธุรกรรม 50,000 รายการ (`TXN-10001`–`TXN-60000`) ซึ่งทีมวิเคราะห์จากข้อมูลจริงทั้งหมด 100% ครับ
7. **Q: Insight ข้อไหนสำคัญที่สุดต่อการแก้ปัญหายอดขายชะลอตัว?**
   - **A**: การจับคู่ **Cross-Selling / Bundle** ระหว่างหมวด Traffic สูง (`Dry Food / Beverages` 49.7% ของบิล) กับหมวด Margin สูง (`Household / Personal Care` 79.78% ของรายได้) เพราะ `Corr(Price, Total_Amount) = +0.8123` ครับ
8. **Q: มั่นใจได้อย่างไรว่าตัวเลขบนสไลด์ บนเว็บ และในรายงานตรงกันทั้งหมด?**
   - **A**: เรามีชุดทดสอบอัตโนมัติ `test_clean_data.py` และ `test_web_data.py` (ผ่านครบ 7 tests, `0 / 49,200` row mismatches) และสร้างกราฟบนสไลด์โดยดึงตรงจากไฟล์ `merged_cleaned.parquet` เดียวกันครับ
